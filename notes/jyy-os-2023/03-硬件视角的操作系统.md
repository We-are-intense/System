## 核心观点

### 1. 整个计算机系统也是一个状态机

上一讲说程序是状态机，这一讲把视角拉到整台计算机：

| 要素 | 内容 |
|---|---|
| 状态 | 所有内存和寄存器的值 |
| 初始状态 | **由处理器手册规定**（CPU Reset 之后的状态） |
| 状态迁移 | 任选一个处理器：如果有外部中断就响应中断，否则从它的 PC 取一条指令执行 |

> 我的理解：注意状态迁移里的"任选一个处理器"和"响应中断"。这两点在硬件模型里第一次出现，分别埋下了**并发**（多个处理器同时推进状态）和**中断**（外部事件打断指令流）两条主线。

### 2. 硬件和程序员的约定

既然是状态机，那"运行什么程序"就完全取决于初始状态和初始状态下 PC 指向的代码。厂商和程序员之间有三层约定：

1. **CPU Reset 后的寄存器状态**：手册写得清清楚楚。例如 x86 Reset 后 `EIP = 0xfff0`，处理器处于 16 位模式，中断关闭。
2. **Reset Vector**：处理器从一个固定地址开始取指令。MIPS 是 `0xbfc00000`，ARM 是 `0x00000000`（可配置），RISC-V 由实现自己决定。
3. **Firmware**：Reset Vector 处放的是厂商提供的固件代码。它本身就像一个小操作系统，负责初始化、配置硬件，**然后把真正的操作系统从存储设备加载进内存**。

### 3. 启动流程：从 Reset 到操作系统

**Legacy BIOS 的约定：**

```
CPU Reset
  → 从 Reset Vector 跳进 BIOS
  → BIOS 初始化硬件
  → 把第一个可引导设备的前 512 字节（MBR）加载到物理地址 0x7c00
  → 跳到 0x7c00 执行（此时仍是 16 位模式）
  → 控制权回到程序员手里
```

MBR 只有 512 字节，扣掉 64 字节分区表和 2 字节结束标识，代码最多 446 字节。但这已经够了：用它把后面更大的加载器或内核读进内存就行。

**UEFI** 是现代的替代方案。今天的固件要面对指纹锁、USB 网卡、蓝牙键盘等各种需要驱动的设备，BIOS 已经碎片化，于是有了统一标准：

- 磁盘用 GPT 分区，预留一个 FAT32 的 EFI 分区
- 固件能加载任意大小的 `.efi` 可执行文件，没有 512 字节的限制
- 有设备驱动框架，支持 Secure Boot（只启动受信任的操作系统）

### 4. 计算机系统里没有魔法

讲次页里有一个很好的例子：在 CPU Reset 的瞬间检查内存，`0x7c00` 处**并没有** MBR 的内容。这证明 MBR 是固件后来加载进去的，不是一开机就在那里。再用 gdb 的 watchpoint 监视 `0x7c00`，就能精确定位到固件里执行加载的那条指令。

**计算机系统的一切行为都是可观测、可理解的。** 观测手段：

- **模拟器**：QEMU（Fabrice Bellard 的作品，Android 模拟器、VirtualBox 背后都有它）可以从 Reset 后的第一条指令开始调试
- **真机**：JTAG 调试器通过硬件调试寄存器，也能提供 gdb 接口

### 5. 最小的"操作系统"就是一个 C 程序

要让一段 C 代码在裸机上跑起来，需要准备：

- MBR 里的**启动加载器**（boot loader）：从 16 位切到 32 位，再把磁盘上紧跟着的 ELF 文件加载进内存，跳到它的入口
- 编译器选项：静态链接、freestanding（不用任何标准库）
- 自己实现的库函数：`putch`、`printf` 等

做到这些，就能跑一个"操作系统"：两个线程分别不停地打印 `a` 和 `b`，并发执行。

> 我的理解：jyy 反复强调"操作系统真的就是个 C 程序，只是能直接访问硬件"。它特殊的地方只有两点：**它是 Reset 之后最先拿到控制权的程序**，以及**它能执行特权指令、控制中断**。

### 6. 读复杂代码的方法：先造理解工具

课上演示了怎样看懂 AbstractMachine 复杂的构建过程：不硬啃 Makefile，而是用 `make -nB` 打印出所有实际执行的命令，再用 `grep` 过滤掉无关的行，用 `sed` 把绝对路径换成相对路径，最后放进编辑器里看。

**花几分钟造一个小工具，把复杂过程拆成可理解的单点。** 这个方法对读 xv6 和 Linux 同样适用。

## Slides 逐页摘要

### 3.1 回顾：计算机硬件（3 页）

1. 标题页。
2. 计算机硬件就是数字电路，可以用 Logisim 这样的模拟器来模拟。能写出模拟器，就说明完全掌握了系统的行为，因为程序是严格的数学对象。
3. 计算机硬件的状态机模型：状态是内存和寄存器；初始状态由手册规定（CPU Reset）；迁移是任选一个处理器，响应中断或取指令执行。由此引出问题：谁定义了状态机的行为？我们怎么控制运行哪个程序？

### 3.2 硬件与程序员的约定（10 页）

1. 标题页。
2. 裸机和厂商的约定：Reset 后的寄存器状态、内存映射 I/O、厂商提供的 firmware（管理硬件，把存储设备上的代码加载进内存）。
3. x86 的 CPU Reset：Intel 手册规定了初始寄存器值，`EIP = 0xfff0`，处于 16 位模式，中断关闭。手册超过 5000 页，最需要的 Volume 3A 也有约 400 页。
4. 其他平台：MIPS、ARM、RISC-V 的 Reset Vector 各不相同；开发板直接把加载器写进 ROM；QEMU 的 `-kernel` 选项可以绕过固件直接加载内核。
5. x86 Reset 之后执行了什么：Reset Vector 处是一条跳进固件的 `jmp`。固件分 Legacy BIOS 和 UEFI 两种。BIOS 有统一规范，这才有了 IBM PC "兼容机"。
6. 为什么需要 UEFI：今天的固件要应付大量需要驱动的设备，BIOS 已经碎片化。
7. Legacy BIOS 的约定：把第一个可引导设备的前 512 字节加载到 `0x7c00`，处理器处于 16 位模式；最多 446 字节代码，但控制权已经回到了程序员手里。
8. 能不能看到每一条指令的执行？能：模拟器用 QEMU，真机用 JTAG 调试器。
9. UEFI 的加载流程：GPT 分区 + FAT32 的 EFI 分区，能加载任意大小的 `.efi` 文件，支持 Secure Boot。
10. 插曲：1998 年的 CIH 病毒利用某些芯片组允许改写 Flash ROM 的特性，直接破坏 BIOS。

### 3.3 实现最小"操作系统"（10 页）

1. 标题页。
2. 已有的能力：能让机器执行任意不超过 510 字节的指令序列，用它把磁盘上的代码加载进内存、初始化 C 运行环境，操作系统就开始运行了。
3. 心里没底很正常。大学的意义在于迅速吸收几十年积累的学科体系，打破"写操作系统很难、很牛"这类错误认识。
4. 裸机上运行 C 代码需要：MBR 里的启动加载器、静态链接和位置无关代码、freestanding 编译、自己实现库函数。
5. 框架代码很复杂，读 Makefile 很费劲，容易本能地放弃。更好的做法是先花点时间造一个"帮助理解的工具"。
6. 先试试 AI：它能正确理解 Makefile 的主干，但会漏掉细节，还夹带很多套话。
7. 观察构建过程的正确方法：`make -nB` 列出所有命令，用 `grep`、`sed` 清理后放进 vim 里看。
8. 进一步改善可读性：按选项拆行，逐个理解编译选项（`-m64`、`-mno-sse` 等）和链接选项（`-Ttext-segment=0x00100000` 等）。
9. 启动加载器：从 16 位切到 32 位，按约定的磁盘格式把 ELF 加载进内存，最后跳到 ELF 的入口地址。代码在 `am/src/x86/qemu/boot/` 下，都可以调试。
10. 我们承诺的"操作系统"就是一个 C 程序：支持两个固定线程，一个不停打印 `a`，一个不停打印 `b`，并发执行。

## 对照：iOS / macOS 上的同一件事

| 课上讲的 | Apple 平台上的对应 |
|---|---|
| Reset Vector 处的固件 | 芯片内固化的 **Boot ROM**，不可修改，是整条信任链的根 |
| BIOS / UEFI 加载操作系统 | Boot ROM → **iBoot**（Apple Silicon Mac 上中间还有一级 LLB）→ XNU 内核 |
| UEFI Secure Boot | Apple 的**安全启动链**：每一级都校验下一级的签名，iPhone 上无法关闭 |
| CIH 改写 BIOS | Boot ROM 只读，所以 Boot ROM 漏洞（例如 checkm8）无法通过软件更新修复 |

## 和 xv6 的连接

xv6-riscv 的启动流程是这一讲的一个精简实例：

1. QEMU 用 `-kernel` 直接把内核加载到 `0x80000000`，绕过了固件这一步（正对应 3.2 第 4 页）。
2. `kernel/entry.S`：每个 CPU 设置好自己的栈，然后跳进 C 代码 `start()`。
3. `kernel/start.c`：在最高特权级 M-mode 下做配置（设置时钟中断等），然后用 `mret` 切到 S-mode，进入 `main()`。
4. `kernel/main.c`：初始化各个子系统，创建第一个用户进程。

这和"准备好栈 → 跳进 C 代码 → 操作系统开始运行"是同一个套路。
