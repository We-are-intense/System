## 核心观点

### 1. 教科书定义没什么用，要理解"全部"

教科书（OSTEP）把操作系统定义为"让程序容易运行、共享内存、和设备交互的一堆软件"。jyy 的态度是：定义只是"全部"的极简压缩，想真正理解，就得看操作系统是**怎么一步步演化成今天这样的**。

理解操作系统有三条线索：

- **硬件**（计算机）
- **软件**（程序）
- **操作系统**：夹在两者之间、管理硬件和软件的软件

### 2. 操作系统的演化：硬件和软件推着它走

| 年代 | 硬件 | 软件 | 操作系统 |
|---|---|---|---|
| 1940s | 电子管逻辑门、延迟线存储、纸带 | 打印平方表、算弹道 | **没有**：程序直接用指令操作硬件 |
| 1950s | 晶体管、磁芯内存、I/O 变丰富；**I/O 远慢于 CPU，中断机制出现（1953）** | Fortran（1957）等高级语言 | **批处理**：库函数，加上自动"换卡"排队运行程序的调度代码；开始出现"设备""文件""任务"这些对象 |
| 1960s | 集成电路、总线；**虚拟存储出现**；中断 / 异常机制完善 | COBOL、BASIC 等 | **多道程序**：内存里同时放多个程序；有了**进程**的概念；一个进程做 I/O 时把 CPU 让给别人；地址空间隔离，一个程序的 bug 不会拖垮整个系统；再进一步"定时切换"，就成了**分时系统**（Multics，1965） |
| 1970s+ | 个人电脑；CISC、MMU、网络 | C（1972）等 | **UNIX** 奠定现代操作系统的形态：信号、管道、socket、procfs……之后衍生出 BSD、macOS、Linux、Windows NT、iOS、Android |
| 今天 | 大小核异构、NUMA、虚拟化扩展、TrustZone、GPU / SSD 等 | 服务器到 IoT | 通过**虚拟化**硬件资源为程序提供服务，是人类造过最复杂的系统之一 |

> 我的理解：这张表最值得记住的是因果关系。**中断**是因为 I/O 太慢才出现的；有了中断和虚拟存储，才可能做**多进程切换**；切换一旦能"定时"触发，就成了**分时**。这正是后面并发、进程、中断几讲的历史起点。

### 3. 本课程的范围

- **软件**：多线程 Linux 应用程序
- **硬件**：现代多处理器系统
- **设计视角**：操作系统提供哪些服务？操作系统 = 对象 + API（POSIX 加上部分 Linux 特性）
- **实现视角**：这些服务怎么实现？操作系统 = C 程序（用 xv6 和自制的迷你操作系统来讲）

### 4. 学习方法

- 用代码模拟一切：数字电路可以用程序模拟（Logisim demo），CPU 也可以用程序模拟（RVEmu demo，指令和设备实现完整的话能直接启动 Linux）。**会编程，就能把任何系统变成可以观察的状态机。**
- 先成为合格的 power user：不怕命令行，会查手册、会搜索，出 bug 时相信"机器永远是对的"。
- 最重要的是 **get your hands dirty**。（在我的计划里，这一点用 xv6 上的 gdb 观察式实验代替。）

### 1.2 为什么学操作系统（5 页）

1. 标题页。
2. 先问"为什么要学任何东西"。
3. 以微积分类比：一门学科有启蒙与应用、严格化与公理化、大规模数值计算等几个阶段，学的时候各有侧重。
4. 学习的真正目的是重走"从无到有"的发现过程，最终用于应用和创新。只记结论没有意义，这件事 ChatGPT 已经做得很好了。现代学习方法是借助工具加速探索：numpy、sympy、matplotlib、Jupyter。
5. 学操作系统的理由：每天在用的东西还没搞懂（窗口怎么创建、Ctrl-C 为什么有时退不出、程序怎么把 128 个 CPU 跑满），也实现不出来（浏览器、编译器、游戏外挂、杀毒软件）。这门课补全"编程"的技术体系。

### 1.3 什么是操作系统（24 页）

1. 标题页。
2. OSTEP 的定义：让程序容易运行、共享内存、与设备交互的软件。但这个定义很含糊。
3. 另一种常见说法："管理软硬件资源、为程序提供服务的程序"。
4. 精准的定义没有意义，要理解"全部"。三条线索：硬件、软件、夹在两者之间的操作系统。
5. 复习硬件：数字电路是一个极简的公理系统（导线、时钟、逻辑门、触发器），计算机就建立在它之上。
6. Logisim demo：用程序模拟数字电路。每个时钟周期先算出所有导线的值，周期结束时锁存进寄存器。会编程就能模拟任何数字系统，顺便体会 UNIX 哲学（一个程序只做好一件事，输出可以成为另一个程序的输入）。
7. 复习软件：高级语言 → 指令序列 → 二进制文件 → 处理器执行。
8. RVEmu demo：用程序模拟 RISC-V 处理器。指令和设备实现得够完整，就能直接启动 Linux。
9. 本课程讲狭义的操作系统：硬件和软件之间的中间层，对单机多处理器做抽象，支撑多个程序运行。学术界说的 System 更广，比如分布式系统。
10. ENIAC（1946）：图灵机的数字电路实现，重新编程要重新接线。
11. 1940s 硬件：电子管逻辑门、延迟线存储、纸带输入输出。
12. 1940s 软件：打印平方表、素数表、计算弹道，这也是程序设计课经典习题的来源。
13. 1940s 操作系统：**没有**。能把程序放上去就很了不起了。
14. 1950s 硬件：晶体管、磁芯内存、更多 I/O 设备。**I/O 速度远低于处理器，于是中断机制出现（1953）。**
15. 1950s 软件：Fortran（1957），一行代码一张卡片，80 列的规范沿用至今。
16. Fortran 示例程序：从读卡机读三个整数求和。计算需求开始暴涨。
17. 1950s 操作系统：库函数，加上管理程序排队运行的代码。计算机极贵，由 operator 轮流调度用户。"批处理系统"出现，开始有"设备""文件""任务"这些对象。
18. 1960s 硬件：集成电路、总线、**虚拟存储**，可以同时载入多个程序；中断和异常机制完善。
19. 1960s 软件：COBOL、APL、BASIC 等语言和编译器。
20. 1960s 操作系统：内存里同时放多个程序并调度它们。共享资源以 API 形式管理；**有了进程的概念**；进程做 I/O 时把 CPU 让给别的进程；地址空间隔离，一个程序出 bug 不会拖垮整个系统。再进一步定时切换，就诞生了分时系统 Multics（1965）。
21. 1970s+ 硬件：集成电路大发展，个人电脑兴起；CISC、中断、MMU、网络都已具备。
22. 1970s+ 软件：Pascal、C 等语言；个人开发者登场。
23. 1970s+ 操作系统：分时系统成熟，**UNIX 奠定现代操作系统的形态**（信号、管道、socket、procfs），衍生出 BSD、macOS、Linux、Windows NT、iOS、Android 等整个家族。
24. 今天的操作系统：通过虚拟化硬件资源为程序提供服务。硬件更复杂（大小核、NUMA、虚拟化扩展、TrustZone），设备更多（GPU、SSD），应用场景从服务器一直到手环和 IoT。课程内容：操作系统 = 对象 + API（设计视角），操作系统 = C 程序（实现视角，初始化后就成为中断 / 陷阱 / 异常的处理程序）。

### 1.4 怎样学操作系统（7 页）

1. 标题页。
2. 对教学的反思：教育不是灌满一桶水，而是点燃一把火。过去的操作系统课教材差、没有像样的实验、调试全靠猜。
3. 现代学习方法：读得懂的教科书（OSTEP），问题驱动、用代码说话，借助 strace、gdb 等工具，读 xv6-riscv 和 AbstractMachine 的代码。RTFM、STFW、RTFSC。
4. 前置要求：是一个合格的操作系统用户，会查文档、会搜索，不怕命令行，不怕写几千行规模的代码；出 bug 时相信"机器永远是对的"，然后用正确的工具去调试。不要"架空学习"，基础不够就回头补。
5. 学术诚信：这是自我要求，而不是底线。不公开实验代码，不参考别人的实现。
6. 成为 power user：觉得命令行难用，是因为还没建立信心、没找对资料、没用对工具（例如 man 和 tldr）。
7. Get your hands dirty：听课看书都不是最重要的，独立完成编程作业才能真正理解操作系统。实验分应用视角的 Mini Labs 和实现视角的 OS Labs，全部由 Online Judge 评测。
